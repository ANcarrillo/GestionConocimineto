# Guía para aplicar la entrevista de recolección de información

**Proyecto:** Modelo de Machine Learning para la identificación de estudiantes en riesgo de deserción
**Metodología:** Híbrida Cascada + Scrum
**Autores:** Francy Almario · Andrés Carrillo

La entrevista está dividida por fases de la metodología. Cada fase tiene su propio archivo, con preguntas dirigidas a un tipo de entrevistado distinto. No es necesario aplicar todas las partes a todas las personas.

| `fase7_despliegue.md` | Fase 7 – Despliegue | 7.1 a 7.5 | Oficina de TI / Infraestructura |

## Antes de la entrevista

1. Confirmar fecha, hora, lugar (o enlace de reunión) y duración estimada (30–45 min por parte).
2. Enviar al entrevistado el objetivo del proyecto en un párrafo.
3. Preparar el formato de consentimiento (abajo) y la forma de registro (grabación de audio o notas).
4. Asignar roles: **entrevistador** (hace las preguntas) y **relator** (toma notas).

## Consentimiento informado (leer al inicio)

> Estamos desarrollando, como trabajo de grado, una plataforma web que usa Machine Learning para identificar de forma temprana a los estudiantes en riesgo de deserción. Esta entrevista busca conocer sus necesidades y la información disponible. Su participación es voluntaria; puede no responder cualquier pregunta. La información se usará solo con fines académicos y no se publicarán datos personales. ¿Autoriza que tomemos notas / grabemos la conversación?

## Después de la entrevista

1. Transcribir las respuestas dentro de las 24 horas siguientes.
2. Pasar cada necesidad identificada a la matriz de requerimientos (RF / RNF) — Excel / Google Docs.
3. Convertir cada requerimiento en una historia de usuario en Trello / Jira: *"Como [rol] quiero [acción] para [beneficio]"*.
4. Registrar acuerdos, dudas abiertas y datos de contacto para seguimiento.
